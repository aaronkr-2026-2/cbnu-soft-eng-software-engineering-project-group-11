# FiLog gallery performance follow-up — 2026-10-24

## Scope and confirmed causes

The workspace already contained PhotoKit render-queue, deterministic disposable URI, progressive viewer, grid-windowing and shared-request changes when this pass started. Those edits and the existing FiLog rename were preserved. This pass adds the fixes below; it does not claim authorship or fresh device verification of the earlier work.

| Confirmed cause in the starting workspace | Targeted change |
| --- | --- |
| `app/index.tsx`: `SectionList key={browseMode}` destroyed the list on every filter switch. Section-qualified cell keys also changed when the same Roll moved between groups. | One persistent FlatList with memoized header/Roll rows. Roll keys depend only on saved Roll IDs; header keys depend on groups. Existing grouping, spacing, labels, header and controls remain. A layout effect resets the offset on mode changes to preserve the previous start-at-top behavior without remounting. |
| `src/features/photos/services/PhotoReferenceService.ts`: invalidation allowed old and new generations of the same native asset/tier request to overlap. A late abort from an old consumer could call asset/tier-wide native cancellation after its replacement started. | Cancel and detach pending old-generation requests before notifying library subscribers. Late old aborts cannot cancel the replacement. Already-aborted calls stop before verification/render work. |
| `src/features/photos/hooks/useResolvedPhoto.ts`: decode failure callbacks checked photo identity but not URI. A late thumbnail failure could clear a newer screen-quality source for the same photo. | Match both identity and the source URI captured by the callback before clearing the displayed source. |

## Reviewed paths and safety

Home's `useRolls` already memoizes filtering/grouping and subscribes to specific Zustand collections. Roll Detail memoizes sorted photos and uses selected store fields. Photo tiles use saved photo IDs and viewport windowing. The viewer mounts three slots, preheats neighbours and uses progressive 512px → physical screen → active High Resolution (maximum 4096px) requests. Gestures run on Reanimated's UI thread. Navigation uses the existing Expo Router Stack and themed background; no transition changes were needed. The gallery tabs change grouping, not image color processing.

`modules/filog-photos/ios/FiLogPhotosModule.swift` already uses a serial render queue, PhotoKit cancellation, modification-date-based temporary JPEG paths and bounded cache cleanup. No native source or dependencies changed in this pass. The JS cache still verifies current PhotoKit access and file existence before reuse. Missing, denied and limited assets cannot become ready from a cached preview. Library revision changes still hide old previews until fresh verification; this conservative refresh can visibly show loading and remains a device UX check. Transient screen/high-tier failures retain verified previews through the existing hook path.

No persisted records, original images, Roll IDs, metadata, sort order, Copy records, identifiers, reference recovery or CloudKit behavior were changed. No data was reset. No fade animation was added.
