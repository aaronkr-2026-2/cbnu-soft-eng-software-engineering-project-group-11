# Reference-only MVP

New multi-photo imports use the local FilmerPhotos Expo module's public PhotoKit / UICollectionView grid. Apple's ordered PHPicker disables swipe-to-select, so it cannot satisfy both ordered selection and range dragging. Single-photo Relink keeps PHPicker. The grid fetches cell-sized disposable thumbnails, never exports originals, and returns only PhotoKit asset identifiers; the provider verifies every identifier before creating a Reference. Missing/null identifiers are rejected with a recoverable access message. `PhotoImportService` retains commit-before-publish behavior.

Tap toggles a photo. Start dragging horizontally on a thumbnail, then move across rows; reverse dragging restores the previous range, and dragging from an already selected photo deselects the range. A vertical start scrolls normally. Holding a selection drag near the grid edges auto-scrolls. Numbered badges and a localized count show selection order. Clear deselects all; Cancel makes no archive write; Add commits the verified batch once. Reimporting an already referenced asset into the same Roll skips that duplicate without changing existing frames. Limited permission displays only accessible assets, with a Manage Access action. This custom import grid intentionally has no album/search UI. Physical-device gesture/performance verification remains required.

`PhotoReferenceService` is the async resolver. Never display a Reference's legacy thumbnailUri or use it as an export fallback. `resolvePhotoUri` is synchronous compatibility code for Documents Copy records only. Session caches verify availability before reuse, regenerate purged files, coalesce requests and invalidate on AppState/library changes. Native PhotoKit derives appropriately sized temporary JPEG renders, explicitly allows iCloud network access, and never mutates originals. Full resolution is requested for the active Viewer or an explicit share/save operation; contact sheets use bounded 1200px requests.

Viewer contains localized Retry and Relink controls. Limited lookup failure is ambiguous, so it is not called deletion. Denied opens Settings; limited Retry uses `presentPermissionsPicker`. A replacement is verified before writing, with photo/roll identity, ordering and original details preserved. Old picker-URI-only records remain in the archive, unavailable until explicitly relinked.

Copy code remains for compatibility and future work. A previously saved Copy preference does not enable Copy import in the MVP. Copy paths still resolve relative to Documents; cleanup only deletes correctly owned files after successful persistence and protects shared paths.

See root `RELEASE_READINESS.md` for validation/recovery rules, exact changed files, commands and the mandatory iPhone test matrix. This module requires a rebuilt native app; Expo Go and a Metro reload cannot provide it. No backend, destructive migration, Photos deletion or backup/restore feature is introduced.
